一句话定义
这是一个位于模型 / Agent 与真实游戏之间、同时拥有对话页和分析页的 AI 游戏 Harness； 它复用 DSH 的通用 Agent 能力，把跨游戏能力做成标准 DSH 插件，把单个游戏的 AI 语义放进 Harness Plugin，并把必须进入游戏进程的部分压缩成薄 Native Bridge。
00 · Positioning

它本身就是 Harness

它是基于 DeepSeek Harness Runtime 构建的游戏产品发行版：继承通用 Agent 与插件能力，再增加游戏领域插件、桌面界面、Game Pack 和 Native Bridge 体系。

What it is

DSH 的游戏发行版

复用 DSH Runtime，连接模型、Agent、玩家与游戏，持续处理观察、理解、决策、执行、回执和呈现。

Product form

独立桌面应用

用户安装的是已经打包 DSH Runtime 与游戏插件的完整产品，不需要预先安装另一个 DSH 应用。

How games join

一游戏一 Harness Plugin

插件拥有游戏知识、语义工具与编排；薄 Mod 只暴露状态、事件和原生动作 API。

What it is not

不重写 DSH，也不替代游戏

不重造模型、Agent、Tool 与 Session 基础设施，也不接管渲染、物理、逐帧战斗和游戏规则权威。

01 · Principles

六条不可动摇的原则

每个架构决策都应该能回到这些原则；不能解释的复杂度，就不应该进入核心。

P / 01

复用 DSH 通用运行时

模型、Agent、Tool、Session、配置、凭据、权限和插件生命周期沿用 DSH；产品差异集中在游戏领域，不重复造轮子。

P / 02

游戏能力首先是 DSH 插件

记忆、语音、视觉、UI、安装、Transport 与每游戏语义工具都遵循 DSH 插件生命周期，不写进 Electron Main 或游戏 Mod。

P / 03

Mod 必须薄

游戏侧只依赖版本化线协议，封装真实状态、事件和原生动作 API；不调用模型、不做规划、不保存 Harness 记忆。

P / 04

事实先于推测

当前状态和动作结果来自游戏 API；视觉与模型负责理解和表达，不能伪造确定性执行结果。

P / 05

界面是一等产品能力

对话、分析、权限、记忆和诊断不是附属工具，而是玩家理解并信任 AI 的核心表面。

P / 06

版本固定，升级可验证

固定 DSH 及其命名空间 Cordis 的兼容版本；升级通过独立变更、Fake Game、协议兼容与真实游戏测试，不自动追新。

三层架构，一个清晰边界

03 · Game Pack

剧情、玩法和代码分别放哪

Game Pack 是一个游戏的完整发行单元：Harness Plugin 安装进 DSH Profile，Native Bridge 安装进游戏 Mods 目录，内容与版本信息把两者组成一次安装。

Game authority

Native Bridge 与游戏本体

Bridge 只封装原生 API；Harness Plugin 才负责调用、组合与解释，游戏本体始终拥有真实状态和最终执行结果。

Bridge：状态、事件与细粒度原生动作 API
Bridge：游戏侧最终校验与权威回执
游戏：战斗、移动、寻路与经济系统
游戏：任务完成、物品、金钱与胜负
game-pack.json manifest → harness-plugin.tgz + native-bridge.zip + content + compatibility + checksums + uninstall
能用数据描述放进配置与内容文件
需要知识、工具或算法做成 DSH Harness Plugin
必须调用游戏原生 API放进薄 Native Bridge
决定真实游戏结果留在游戏本体
权威状态原则 凡是影响胜负、物品、金钱、任务完成、角色死亡、地图变化或存档进度的状态，都必须由游戏本体保存并通过 Native Bridge 返回确认；模型不能仅凭文字宣告其生效。
04 · Protocols

插件协议与线协议，各司其职

DSH/Cordis 插件协议解决 Harness 内能力如何装配；Bridge Contract 解决 Harness Plugin 如何跨进程调用不同语言的游戏 Mod。Transport 是插件，线上消息格式是独立契约。

DSH / Cordis Plugin Protocol

直接沿用 DSH 的 Context、服务、事件、依赖和可逆生命周期。Cordis 按常见英文读法读作 COR-dis，中文近似“科尔迪斯”。

TypeScript / JavaScript同进程@deepseek-ai/*标准 DSH 插件
✓复用 DSH 的模型、Agent、Tool、Session、Settings、Credentials 与 Approval 能力。
✓Game Core、Transport、Memory、Media、UI、Installer 与每游戏 Harness 都是 DSH 插件。
✓固定整套 DSH 与命名空间 Cordis 兼容版本并提交 lockfile；升级执行兼容测试。
×不混用独立 cordis 与 @deepseek-ai/cordis，避免 Context、类型和 peer dependency 分裂。

Native Bridge Contract

由本项目定义的公开线协议，从原型项目 protocol/v1.1 演进；它面向跨进程、跨语言和游戏权威状态。Mod 不需要也不能实现 DSH 插件协议。

WebSocketJSON-RPC 2.0JSON Schema跨进程
✓Bridge 上报游戏身份、原生 API 能力、状态、事件和动作结果。
✓协议不包含 Provider Key、厂商消息结构和模型隐藏推理。
×原始音视频和逐帧控制不塞进 JSON；大数据使用独立媒体通道。
{ "jsonrpc": "2.0", "method": "bridge.hello", "params": { "gameId": "my-native-game", "bridgeId": "official-native-bridge", "protocolVersion": "1.1", "capabilities": ["state", "events", "actions"] } }

代码已经走到桌面开发预览

APP

Windows 桌面开发包

Electron 已能启动内置 DSH、隔离用户 Profile、装配小汤圆 0.7.7 和独立 ONI Adapter 0.1.5，并生成 NSIS .exe。星露谷/饥荒按 V，缺氧按 Q；目前仍是未签名的本地开发产物。

06 · Repository structure

目录表达边界，不只是整理文件

按运行进程、复用范围、依赖方向和发行单元拆分。除了桌面启动壳、线协议、游戏内 Mod 与打包元数据，产品运行能力都应实现为 DSH 插件。

APP

apps / runtime

apps/desktop 只管理窗口与 DSH 子进程；runtime/dsh-profile 固定上游版本、默认配置与插件装配，不自研另一套 Runtime。

PLUG

plugins

Game Core、Transport、Memory、Media、UI、Installer 等跨游戏能力只实现一次，并遵循 DSH 的注入、事件和可逆生命周期。

WIRE

contracts

独立定义 Harness 与 C#、Lua、C++ Mod 共同使用的 Bridge 消息和 Schema，避免线协议反向依赖某个 TypeScript 插件。

GAME

games / <game>

同一游戏的 Harness Plugin、薄 Native Bridge 与 Pack 放在一起，确保它们共同测试、固定兼容范围并作为一个 Game Pack 发行。

TEST

tests

分别验证协议兼容、DSH 插件装配、Trace 回放和最终游戏状态，明确区分“能够构建”和“真的执行成功”。

SHIP

distribution

将桌面源代码组合成完整应用，将每游戏两端代码组合成 Game Pack；发行物拥有独立版本、校验和、兼容范围与卸载信息。

单向依赖规则 Desktop → DSH Profile → Shared Plugins → Game Harness Plugin → Bridge Contract → Native Bridge → Game API。Mod 不反向依赖 Harness，通用插件也不依赖某个具体游戏。
07 · Product surfaces

引擎必须“看得见”

当前桌面壳承载 DSH Web 对话与启动状态；下面的分析页和连接中心是明确的产品方向，不能误写成已经全部实现。

NOW

桌面程序负责启动和停止内置 Runtime，启动中或失败时显示状态，成功后加载 DSH Web；对话、模型和工具界面复用 DSH。

NEXT

NEXT

规划：游戏连接中心

管理 Game Pack、Harness Plugin、Native Bridge、协议版本、权限、安装更新和诊断，让接入状态一眼可见。

10 · Boundaries

我们做什么，也明确不做什么

清晰的非目标能防止引擎重新膨胀成另一个面向所有场景的通用 Agent 产品。

● Harness 承诺

  • 完整打包并复用经过验证的 DSH Runtime
  • 标准 DSH 游戏插件与可独立安装的 Game Pack
  • 稳定、跨语言、可测试的 Native Bridge Contract
  • 基于事实的游戏状态与动作回执
  • 本机优先的权限、记忆和隐私边界

● 明确非目标

  • 不重写 DSH 已有的模型、Agent、Tool 与 Session
  • 不要求游戏 Mod 使用 TypeScript 或 Cordis
  • 不把规划、记忆和模型调用塞进游戏 Mod
  • 不取代 Unity、Godot 或游戏自己的运行时
  • 不让远程模型控制逐帧战斗和寻路
原项目是历史原型，新项目现在同时是源码与产品本体。

dsh-xiaotangyuan-game 验证过的多游戏桥接、跨语言 JSON-RPC、记忆、视觉、语音与流式回复源码现已迁入 ai-native-game-harness。今后的源码、测试、文档与新 Release 只在主仓库维护；桌面版直接从 plugins/xiaotangyuan-game 构建，不再读取相邻旧仓库。旧仓库仅保留历史记录和已经发布的静态下载文件，不是第二条开发线。新产品沿用 DSH 与其 @deepseek-ai/cordis 插件体系，游戏差异位于 Harness Plugin，游戏进程只保留薄 Native Bridge。
