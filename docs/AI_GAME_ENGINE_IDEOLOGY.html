一句话定义
这是一个位于模型 / Agent 与真实游戏之间、同时拥有对话页和分析页的 AI 游戏 Harness； 它承载并编排跨游戏的 AI 能力，把具体游戏差异压缩成 Adapter，把剧情与玩法资产组织成 Game Pack。
00 · Positioning

它本身就是 Harness

Harness 不是借来的品牌词，而是产品类别：负责把模型、上下文、工具、游戏状态、动作权限和用户界面组装成可运行、可观察、可控制的闭环。

What it is

AI 游戏运行底座

连接模型、Agent、玩家与游戏，持续处理观察、理解、决策、执行、回执和呈现。

Product form

有界面的 Harness

对话页面向玩家，分析页面向理解与诊断，Adapter 中心面向连接、权限和能力管理。

How games join

一游戏一 Adapter

游戏只暴露状态、事件、动作与呈现能力；Harness 不要求开发者重做模型和 Agent 基础设施。

What it is not

不替代游戏引擎

不负责渲染、物理、逐帧战斗或游戏规则权威，也不是 DeepSeek Harness 的转接器或外壳。

01 · Principles

六条不可动摇的原则

每个架构决策都应该能回到这些原则；不能解释的复杂度，就不应该进入核心。

P / 01

Harness 拥有通用能力

模型、Agent、记忆、视觉、语音、会话、安全、UI 与诊断只实现一次，不在每个游戏里复制。

P / 02

Adapter 只表达游戏差异

Adapter 提供状态、事件、动作与呈现能力；它不保存模型密钥，也不内置某家模型 SDK。

P / 03

协议优先于实现

游戏侧只依赖版本化的网络协议。C#、Lua、C++、Python 与 JavaScript 都能成为一等公民。

P / 04

事实先于推测

当前状态和动作结果来自游戏 API；视觉与模型负责理解和表达，不能伪造确定性执行结果。

P / 05

界面是一等产品能力

对话、分析、权限、记忆和诊断不是附属工具，而是玩家理解并信任 AI 的核心表面。

P / 06

内部可插拔，对外要简单

Harness 内部采用版本化的 Cordis 风格插件约定；普通游戏开发者只需实现 Adapter，不必学习插件系统。

三层架构，一个清晰边界

Harness 负责 AI 编排，协议负责翻译，游戏负责真实世界。任何能力都应该有唯一所有者。

03 · Game Pack

剧情、玩法和代码分别放哪

Game Pack 是一个游戏在引擎生态中的完整发行单元。它可以组合内容、逻辑、Adapter 和资源，但每种资产仍有清晰所有权。

Game Pack · 一个游戏的完整 AI 接入包 CONTENT × LOGIC × ADAPTER × GAME
Declarative content

剧情与角色配置

策划能够直接阅读、版本化和修改的数据，不需要重新编译引擎。

世界观、人物小传与语言风格
剧情节点、任务目标与触发条件
数值、概率、冷却与关系阈值
角色提示词、知识与本地化
Engine plugins

动态玩法与剧情逻辑

只有需要算法、状态机或持续运行的能力才进入 Engine Plugin API。

动态剧情导演与章节调度
关系网络与长期角色成长
程序化任务与多角色协作
自定义剧情页、关系图和分析面板
Game authority

Adapter 与游戏本体

Adapter 负责翻译；游戏本体始终负责真实状态、硬玩法和最终执行结果。

Adapter：状态、事件、动作 Schema
Adapter：校验参数并调用游戏 API
游戏：战斗、移动、寻路与经济系统
游戏：任务完成、物品、金钱与胜负
game-pack.json manifest → adapter + content/stories + content/characters + gameplay/balance + optional plugins + ui + assets
能用数据描述放进配置与内容文件
需要运行算法做成 Engine 插件
依赖具体游戏 API放进 Adapter
决定真实游戏结果留在游戏本体
权威状态原则 凡是影响胜负、物品、金钱、任务完成、角色死亡、地图变化或存档进度的状态，都必须由游戏本体保存并通过 Adapter 返回确认；模型不能仅凭文字宣告其生效。
04 · Protocols

两类扩展边界，各司其职

Cordis 风格插件约定解决“通用能力如何扩展”，Game Adapter Protocol 解决“任意语言的游戏如何接入”。二者服务的对象、进程边界和安全模型不同，不能强行合并。

Harness Plugin Protocol

Harness 内部扩展约定，遵循 DeepSeek Harness 所采用的 Cordis 核心形态：服务、事件、依赖注入与可逆生命周期。

TypeScript / JavaScript同进程Cordis受控扩展
✓模型、记忆、语音、视觉、分析面板和角色包可以是插件。
✓沿用 name / inject / apply / ctx.effect / ctx.on 的核心契约，并自行版本化。
×这不是行业统一标准，也不承诺所有 DSH 插件无需修改即可运行；项目不再建设 DSH 兼容适配层。

Game Adapter Protocol

由本项目定义的公开协议，从原型项目 protocol/v1.1 演进；它面向跨进程、跨语言和游戏权威状态，不套用 Harness 内部插件协议。

WebSocketJSON-RPC 2.0JSON Schema跨进程
✓Adapter 上报游戏身份、能力、状态、事件和动作结果。
✓协议不包含 Provider Key、厂商消息结构和模型隐藏推理。
×原始音视频和逐帧控制不塞进 JSON；大数据使用独立媒体通道。
{ "jsonrpc": "2.0", "method": "adapter.hello", "params": { "gameId": "my-native-game", "adapterId": "official-adapter", "protocolVersion": "1.1", "capabilities": ["state", "events", "actions"] } }
05 · Product surfaces

引擎必须“看得见”

界面让玩家与开发者理解 AI 正在做什么、依据是什么、权限在哪里，而不是面对一个黑盒后台进程。

CHAT

对话页面

实时流式对话、语音、取消与重试；明确展示工具动作、成功结果和可恢复错误。

DATA

分析页面

展示结构化游戏状态、最近事件、记忆命中、可用动作、延迟与费用；不展示隐藏思维链。

LINK

Adapter 中心

管理游戏连接、协议版本、能力列表、权限、安装更新和诊断，让接入状态一眼可见。

06 · Ecosystem

不同参与者，只承担必要复杂度

生态的关键不是让所有人写插件，而是让每一种参与者只接触与自己相关的那层。

Game developer

游戏开发者

实现 Game Adapter Protocol，提供状态、事件、动作和游戏内呈现。

Harness developer

Harness 开发者

维护 Agent、协议、UI、安全、版本兼容与跨游戏基础设施。

Plugin author

能力开发者

通过 Harness Plugin Protocol 扩展模型、语音、记忆、视觉或分析面板。

Player

玩家

安装一个应用、连接自己的游戏、选择角色与模型，不需要理解 Harness。

08 · Boundaries

我们做什么，也明确不做什么

清晰的非目标能防止引擎重新膨胀成另一个面向所有场景的通用 Agent 产品。

● Harness 承诺

  • 统一 AI 游戏运行时和可见界面
  • 稳定、跨语言、可测试的 Adapter 协议
  • 基于事实的游戏状态与动作回执
  • 本机优先的权限、记忆和隐私边界
  • 一次接入，多种模型、角色和内容包可复用

● 明确非目标

  • 不做 DeepSeek Harness 的兼容层或替代发行版
  • 不要求游戏 Adapter 使用 TypeScript 或 Cordis
  • 不取代 Unity、Godot 或游戏自己的运行时
  • 不让远程模型控制逐帧战斗和寻路
  • 不把模型隐藏推理作为分析页面内容
原项目是能力原型，新项目是产品本体。

dsh-xiaotangyuan-game 已验证多游戏桥接、跨语言 JSON-RPC、记忆、视觉、语音与流式回复；ai-native-game-harness 用独立名称和边界承载未来产品。二者有技术血缘，但新产品不依赖 DeepSeek Harness 才能成立。
