# 办公模块黄金验收

目标不是检查“模型说完成了”，而是确认玩家能够在游戏里交付工作、持续修改，并拿到真实可打开的成果。

## 自动化门槛

| 场景 | 必须满足 |
| --- | --- |
| 联网 HTML 汇报 | 实际调用联网搜索；生成有效 HTML；打开的就是该 HTML |
| Markdown/文档 | 文件非空、类型正确；返回绝对路径；可由系统默认程序打开 |
| PPT | 生成真实 PPT/PPTX；不能用改后缀的文本冒充；打开本次成果 |
| Excel | 生成真实 XLS/XLSX/CSV；不能用空文件冒充；打开本次成果 |
| 反馈迭代 | 查询思路、修改意见和打开成果继续使用同一 Work Session |
| 异常恢复 | 首次没有真实执行时只在同一 Session 自纠一次；仍失败则自然报告失败，不得假装完成 |

自动测试分别覆盖：

- `plugins/dsh-work-orchestrator/test/work-orchestrator.test.ts`：工具范围、成果证据、联网证据、精确打开目标和一次自纠。
- `tests/integration/office-work-golden-e2e.test.ts`：HTML、Markdown、PPT、Excel 四类成果契约。
- `tests/integration/dual-session-e2e.test.ts`：小汤圆先回复、后置分类、同一 Work Session 持续处理、进度与反馈复用、玩家界面不泄露内部术语。

## 最终人工验收

自动化通过后，只需在真实星露谷里确认：

1. 按 `V` 后小汤圆先快速、简短回应。
2. 说“联网查资料，做一个 AI 改变游戏的 HTML，完成后打开”。
3. 等待主动通知，确认通知不是整篇文档。
4. 问“思路是什么”，再说“第二部分不对，改短一点”。
5. 说“打开最终成果”，确认系统浏览器打开正确文件。
6. 确认气泡在语音播放结束约 5 秒后消失，游戏没有被后台工作阻塞。

自动测试不能替代真实麦克风、语音合成、气泡时序和系统默认程序的最终人工确认。
