01 · POSITIONING

先把一句话
说清楚

AI Native Game Harness 是基于 DSH Runtime 构建的游戏领域发行版。它复用成熟的模型、Agent、Tool、Session、凭据与插件体系，只新增游戏真正缺少的领域边界。

ONE-SENTENCE DEFINITION

复用 DSH 通用运行时，用 Harness 组织游戏语义，用薄 Adapter / Mod 连接原生 API，并让游戏本体保持事实权威。

REUSE

通用能力不重造

模型、Agent、Tool、Session、语音、视觉、记忆与凭据优先复用 DSH 和共享插件。

DOMAIN

游戏差异放进插件

每款游戏的知识、语义工具、剧情边界和展示逻辑由独立 Harness Plugin 拥有。

BRIDGE

游戏 Mod 保持薄

只暴露真实状态、事件和原生动作；不调用模型、不做规划、不保存 Harness 记忆。

AUTHORITY

游戏拥有最终事实

胜负、物品、任务、地图、存档和动作结果必须由游戏 API 返回确认。

02 · PRINCIPLES

七条原则，
分成三组理解

原则不是口号，而是遇到“要不要重写、功能放哪、模型能否相信”这些决策时的判断顺序。

A
BASELINE

先复用，再谈替换

P01
复用 DSH 通用运行时

项目集中解决游戏领域问题，不重复造一套 Agent Runtime。

P06
版本固定，升级可验证

升级先通过 Fake Game、协议兼容和真实存档验收。

P07
替换基础能力必须先举证

只有可复现测试证明具体能力不匹配时，才建立最小替代。

B
OWNERSHIP

让职责待在正确的位置

P02
游戏能力首先插件化

记忆、语音、视觉、UI、Transport 和游戏语义工具都能独立启停与测试。

P03
游戏 Mod 必须薄

原生侧只负责状态、事件、动作和权威回执。

C
TRUST

事实与体验共同建立信任

P04
事实先于模型推测

视觉负责理解，模型负责决策；确定性结果来自游戏 API。

P05
界面是一等产品能力

权限、记忆、动作结果和诊断必须对玩家可见、可理解。

默认决策

DSH 已有能力 → 直接复用　·　能力存在但边界不合适 → 写适配层　·　可复现测试证明缺口 → 最小替代

04 · PROTOCOL & DISTRIBUTION

一游戏一包，
两类协议

发行单元和通信边界必须分开理解：Game Pack 负责“这款游戏需要什么”，协议负责“这些能力如何装配与通信”。

ONE GAME · ONE GAME PACK

不同游戏按需加载，不塞进核心

用户只安装自己需要的游戏，开发者也能单独版本化、升级和卸载。

PLUGINHarness Plugin知识、Schema、语义工具与编排
CONTENT角色与剧情配置世界观、目标、禁写事实与节奏
BRIDGEAdapter / Mod状态、事件、原生动作和权威回执
MANIFEST安装与兼容信息版本、权限、校验和与卸载记录
INSIDE HARNESS

DSH / Cordis Plugin Protocol

管理 Game Core、Memory、Media、UI、Installer、Transport 与每游戏插件的依赖注入、事件和可逆生命周期。

  • 复用同一个 Agent Session
  • 插件可独立装配和停用
  • 凭据不进入游戏 Mod
ACROSS PROCESSES

Native Bridge Contract

面向 C#、Lua、C++ 等环境，只传递游戏身份、能力、Observation、Event、Action、Result、revision 与错误。

  • 稳定、版本化的 JSON 消息
  • WebSocket 只是默认 Transport
  • 不传 Provider Key 和隐藏推理
HARNESS OWNS

我们负责

  • 完整打包并复用通用 AI Runtime
  • 标准游戏插件与独立 Game Pack
  • 跨语言、可测试的 Bridge Contract
  • 基于真实状态的动作回执和 Trace
NON-GOALS

我们明确不做

  • 不重写已有模型、Agent、Tool 与 Session
  • 不把规划、记忆和模型调用塞进 Mod
  • 不取代 Unity、Godot 或游戏运行时
  • 不让远程模型控制逐帧战斗和寻路

05 · EVIDENCE & ROADMAP

已验证什么，
下一步是什么

构建成功、安装成功和真实游戏长期验收是三件不同的事。这里分别说明，不把路线图写成已经完成。

已验证

Core 与协议

Harness Core、Adapter Protocol、WebSocket Host、Game Pack 注册表和一致性检查已有实现与自动化测试。

已验证

本地桌面发行

Windows 本地安装、启动、卸载和诊断导出已经通过开发环境验收。

已有切片

多游戏接入

Adapter Starter、Mock Game，以及星露谷、饥荒和缺氧的不同语言实现已经进入同一主仓库。

进行中

真实游戏长期验收

继续核对真实存档、连续 StoryBeat、状态事实、动作结果、语音、重连和长期记忆。

PHASE 01 · COMPLETE

最小权威闭环

固定 Runtime，跑通观察、决策、动作、结果、新状态与 Trace。

PHASE 02 · NOW

长期体验验收

把多游戏链路放进真实存档，验证连续运行与失败恢复。

PHASE 03 · NEXT

可信开放生态

完善签名、权限授权、第三方可信启动、目录与认证机制。

源码目录如何表达边界展开查看
apps / runtime

桌面产品、内置 DSH 进程和固定 Runtime Profile。

packages / dsh-binding

把 Agent Tool Call 映射为 Harness action。

plugins

Game Core、Transport、Learning、Story 与游戏插件。

contracts

跨语言 Bridge 消息与 Schema，不依赖 Cordis 类型。

games / <game>

每款游戏的插件、薄 Bridge 与 Pack 共同测试发行。

tests / distribution

协议、装配、状态、Trace、版本和安装包分别验收。
